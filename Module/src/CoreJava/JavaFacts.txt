Constructor Chaining:

In Java, constructor chaining is the process of calling one constructor from another within the same class or from its parent class.
It is primarily used to avoid code duplication and centralize initialization logic.

How it Works
Constructor chaining works by using the special keywords this() and super().
Chaining within the same class: One overloaded constructor calls another using the this() keyword.
Chaining from a parent class: A subclass constructor calls its immediate parent's constructor using the super() keyword.

Essential Rules
First Statement: The call to this() or super() must be the very first line in a constructor.
Mutually Exclusive: You cannot use both this() and super() in the same constructor because both must be the first statement.

Implicit vs. Explicit Chaining:
Implicit: If you do not explicitly call this() or super(), the Java compiler automatically inserts a default super() call to the parent's no-argument constructor.
Explicit: You manually write this(...) or super(...) to call a specific constructor with arguments.
Termination: At least one constructor in the chain must not call this() to avoid infinite recursion.

Order of Execution
Execution follows a "top-down" approach in the inheritance hierarchy:
Parent First: The constructor of the topmost class (e.g., Object) is reached first and executed fully.
Child Second: Execution then flows down the hierarchy until the original subclass constructor completes its logic.
Reverse Order of Calls: While constructors are invoked from the subclass upward to the parent, they finish executing from the parent downward to the subclass.
Alternative: Initialization Blocks
You can also use Instance Initialization Blocks (IIB) for common code across all constructors. These blocks run before any constructor in the class is executed, every time an object is created.

In Java, an Instance Initialization Block (IIB) is a nameless block of code enclosed in braces {} inside a class, but outside any method or constructor. It is primarily used to share common initialization logic across multiple constructors.
Key Characteristics
Automatic Execution: The block runs automatically every time a new object of the class is created.
Precedes Constructor: It executes after the superclass constructor completes but before the current class's constructor body.
Multiple Blocks: A class can have multiple IIBs, and they execute in the order they appear in the source code.
No Keywords: Unlike static blocks, IIBs do not use any keywords like static.

When you instantiate a class, the JVM follows this strict sequence:
Static Initialization Blocks: Run once when the class is first loaded.
Superclass Constructor: The parent class's constructor logic completes first.
Instance Initialization Blocks: The IIBs of the current class execute in order.
Current Class Constructor: The actual body of the constructor being called executes last.
